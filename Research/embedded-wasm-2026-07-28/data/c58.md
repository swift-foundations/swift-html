## Envelope correction: reproduces on macOS-arm64, in a debug build, when the target is wasm32

The issue currently scopes this to release + `-O` + `-enable-default-cmo`, whole-module, Linux x86_64, and prior investigation recorded that it does not reproduce on Apple hardware. **Both halves of that scoping are too narrow.**

Reproduced 2026-07-28 on **macOS arm64**, **debug (`-Onone`)**:

```
swift build --swift-sdk swift-6.3.3-RELEASE_wasm-embedded --target HTML
```

swift-html (swift-foundations), swift.org 6.3.3-RELEASE toolchain via swiftly, host `arm64-apple-macosx`, target `wasm32-unknown-wasip1`. Identical signature:

```
While running pass #2592 SILModuleTransform "CrossModuleOptimization".
Abort: function forAbstract at ASTContext.cpp:5924
Abstract conformance with bad subject type:
  (element_type level=1
    (pack=pack_archetype_type conforms_to="Swift.(file).Copyable"
     conforms_to="Render_Primitive.(file).Render extension.View" name="each Content"
      (interface_type=generic_type_param_type depth=0 index=0 name="Content" param_kind=pack)))
```

Crashing module is `Render_Primitive` (swift-render-primitives), at `Sources/Render Primitive/Render.View.swift:7:21` — a third module, alongside the `Records` and `Structured_Queries_Primitives` cases already recorded, and the third distinct pack archetype (`each Content`, vs `each V`).

### Why the earlier scoping was wrong

**The variable was never the platform — it was whether CMO ran.** Selecting an `-embedded` Swift SDK causes `embedded-toolset.json` to inject `-enable-experimental-feature Embedded -static-stdlib -wmo`, and Embedded mode runs `CrossModuleOptimization` **regardless of optimization level**. That is why a `-Onone` build trips a pass previously believed to require release + `-O`. Host-native macOS builds did not reproduce it because CMO was not running, not because the host was Apple.

`-Xswiftc -disable-cmo` does **not** suppress it — pass #2592 still runs and still aborts.

### Consequence

Reduction no longer requires a Linux x86_64 container. There is now a local macOS repro, which materially lowers the cost of producing the minimal reproducer.

The blast radius is also wider than the 6.4 migration: this blocks **any** Embedded or WebAssembly work in the ecosystem on 6.3.3, independent of toolchain version, because Embedded forces the pass that crashes.

Not yet tested against a 6.4.x snapshot; that is in progress and I will follow up here either way.
